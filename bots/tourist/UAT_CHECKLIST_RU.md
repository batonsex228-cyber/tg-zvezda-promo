# ТУРИСТ v0.14.0 — приёмка перед запуском

Это **практический чек-лист**, а не утверждение, что реальные Telegram / Google / S3 уже проверены. Выполненные локальные тесты не заменяют тесты с двумя настоящими аккаунтами Telegram и телефоном. Отмечайте каждый пункт только после собственного воспроизведения.

## 0. Подготовка

- [ ] Архив v0.14.0 распакован в **новую** папку. `.env` и база из предыдущей версии сохранены отдельно, с проверенной копией.
- [ ] После `SETUP_WINDOWS.bat` прошли `TEST_WINDOWS.bat` и `FIRST_RUN_CHECK_WINDOWS.bat`.
- [ ] Токен создан в **@BotFather**; он хранится только в локальном `.env`, не передаётся в переписке. `DEMO_MODE=false`.
- [ ] `OWNER_TELEGRAM_ID` принадлежит именно клиенту (для Вашего тестового бота — Вашему тестовому владельцу).
- [ ] Не работает другая копия бота с тем же токеном: ни webhook, ни второй long polling.

## 1. Настоящий Telegram — два независимых аккаунта

- [ ] У аккаунта A (`владелец`) команды `/start`, `/id`, `/schedule`, `/app`, `/admin` отвечают без ошибок.
- [ ] Аккаунт B (`гость`) не видит чужую админку и не может вызвать админские API.
- [ ] Аккаунт B проходит `/register` и сохраняет ник. Повтор такого же ника с аккаунта C отклоняется.
- [ ] Аккаунт B записывается на будущую игру. Администратор получает уведомление, подтверждает; B получает итоговое уведомление **ровно в проверенном случае**.
- [ ] После повторного нажатия / временного разрыва сети дубль заявки не создаётся.
- [ ] Запрос отмены B отображается администратору; подтверждение и отказ в отмене ведут к правильному статусу.
- [ ] Бильярд: два человека не могут забронировать один и тот же пересекающийся интервал; независимый интервал доступен.


## 1.1. Повторные запросы и уведомления (новое в v0.14)

- [ ] Гость дважды отправляет один и тот же запрос отмены при статусе `cancel_requested` — без двух уведомлений администратору и без ошибочного сообщения об отмене.
- [ ] Повтор запроса отмены **чужой** заявки запрещён.
- [ ] Публичное расписание не содержит Telegram ID автора мероприятия.
- [ ] Гость и старший администратор не могут вызвать ручной повтор с `/api/admin/notifications/retry`; владелец — может после подтверждения в интерфейсе.
- [ ] Уведомления, которые Telegram уже принял, не ставятся в очередь повторно; постоянные ошибки (например, бот заблокирован пользователем) и напоминания исключены.
- [ ] Владелец знает об ограничении доставки at-least-once: при некоторых сетевых обрывах получатель может увидеть повтор сообщения.

## 2. Настоящая Mini App на телефонах

- [ ] Mini App открывается через кнопку Telegram на **Android**, если Android используется клиентами.
- [ ] Mini App открывается на **iPhone** (при наличии устройства); учтены нижние системные панели и клавиатура.
- [ ] Профиль, расписание, статус брони, бильярд, админ-экран сохраняют данные после полного закрытия и повторного открытия.
- [ ] Вход из обычного браузера без Telegram initData не даёт доступа к заявкам/данным в боевом режиме.
- [ ] После истечения подписи `initData` приложение сообщает об истечении авторизации и предлагает открыть его заново.
- [ ] На медленном интернете нет двойного списания мест/двойной брони; ошибка сети понятна пользователю.

## 3. Google Sheets (опционально)

- [ ] Сервисному аккаунту Google предоставлен доступ к конкретной таблице клиента; JSON-ключ не добавлен в ZIP / Git.
- [ ] `CHECK_GOOGLE_ONLINE_WINDOWS.bat` успешно прочитал метаданные таблицы **без изменения ячеек**.
- [ ] В реальной тестовой таблице выполнена **отдельная проверка записи** `python -m app.cli sync-now`; появились все нужные вкладки.
- [ ] Проверены новые/изменённые гости и статусы заявок после повторной выгрузки и ошибки связи.
- [ ] Клиент понимает, что в Google Sheets передаются имена, телефоны, Telegram ID и заявки; доступ ограничен и согласован.

## 4. Сервер 24/7 и резервные копии

- [ ] У сервера настроены DNS, HTTPS и сертификат; домен контролирует клиент, /ready возвращает HTTP 200.
- [ ] На сервере запущен **один** экземпляр бота. Настроен мониторинг, который сообщит о сбое, а не только докер healthcheck.
- [ ] SQLite регулярно копируется локально. Парольная фраза внешнего шифрованного бэкапа хранится отдельно.
- [ ] Внешний S3: выгрузка и обратная загрузка зашифрованного файла прошли с настоящими, ограниченными правами.
- [ ] **На другом компьютере** выполнено восстановление в новый файл и проверены заявки и пользовательские данные.
- [ ] После перезапуска/обновления контейнера данные и сертификаты сохранились.

- [ ] Утверждены количество столов, рабочие часы, длительности, правила мафии и покера, ограничения, оплата/отмена, стоимость (если есть).
