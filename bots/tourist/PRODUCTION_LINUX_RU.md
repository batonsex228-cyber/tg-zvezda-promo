# ТУРИСТ v0.11.0 — постоянный HTTPS-сервер (Linux VPS + Docker Compose)

> Эта конфигурация **подготовлена и проверена статически/тестами Python**, но Docker Engine, DNS, выпуск сертификатов Caddy, реальный Telegram и внешние интеграции **в данной среде не запускались**. Это инструкция для первичной установки на подконтрольном сервере, а не отметка о завершённой промышленной приёмке.

## Перед началом

- Потребуется собственный VPS на Linux с Docker Engine и Docker Compose v2, доступом к `api.telegram.org`, доменным именем и DNS-записью `A`/`AAAA`, указывающей на сервер.
- Порты **80/TCP и 443/TCP** должны быть доступны извне; **443/UDP** — опционально для HTTP/3. Сертификаты Caddy сможет получить только если домен и сеть действительно настроены.
- На том же самом Telegram-токене не должен параллельно работать старый Windows-бот или другое long-polling/Webhook-приложение.
- Перед переносом существующих данных сделайте независимую SQLite-копию штатным скриптом и проверьте её. Не переносите активные WAL/SHM через проводник.
- Подготовьте учётную запись владельца (`OWNER_TELEGRAM_ID`) и сохраните токен в секрете.

## Первичная настройка

1. Скопируйте содержимое проекта на VPS в отдельный каталог с ограниченными правами. Не размещайте проект в публичной папке веб-сервера.
2. В каталоге создайте `.env` из `.env.example`, установите права `chmod 600 .env`. Установите:
   ```dotenv
   DOMAIN=club.example.ru
   BOT_TOKEN=ВАШ_ТОКЕН_В_ЛОКАЛЬНОМ_ФАЙЛЕ
   OWNER_TELEGRAM_ID=123456789
   DEMO_MODE=false
   CLUB_TIMEZONE=Europe/Moscow
   BACKUP_INTERVAL_HOURS=24
   BACKUP_KEEP_DAYS=14
   ```
   Не отправляйте токен в чат. `WEBAPP_URL` формируется автоматически как `https://${DOMAIN}` при запуске через `compose.yaml`.
3. Запустите `docker compose up -d --build` в каталоге проекта. Запускается **ровно один экземпляр** приложения с Telegram long polling, и отдельный Caddy с TLS. API-порт `8000` в Интернет не публикуется.
4. Посмотрите `docker compose ps`, затем `docker compose logs --tail=100 app` и `docker compose logs --tail=100 caddy` на самом сервере. Убедитесь, что контейнер `app` *healthy*, нет ошибок Telegram, а домен выдаёт HTTPS.
5. Откройте `https://club.example.ru/ready`: ожидается `{"ready":true,"version":"0.11.0"}`. При неисправной базе результат 503 без раскрытия путей или ключей.
6. Отправьте боту `/start`, `/id`, `/schedule`, `/app` и откройте Mini App в настоящем Telegram. Проверьте отдельным аккаунтом запись на игру и её подтверждение администратором.

### Подключение Google Sheets

При необходимости внесите `GOOGLE_SHEET_ID` и `GOOGLE_CREDENTIALS_FILE=/app/data/google-credentials.json` в `.env`. Сервисный JSON необходимо положить в **закрытый том `tourist_data`**, дать чтение пользователю контейнера UID 10001 и не хранить файл в Git или папке сайта. Разрешите доступ к таблице email-адресу service account. После настройки сделайте `docker compose up -d` для пересоздания приложения. Отдельно проверьте выгрузку и повтор после ошибочного запроса.

### Резервирование и восстановление

- Приложение автоматически проверяет и сохраняет локальные **незашифрованные** SQLite-копии в отдельный том `tourist_backups`; это защита от логической ошибки, **не** от потери VPS/диска целиком.
- Для переноса вне сервера создавайте зашифрованный `.tbackup` через `docker compose exec app python -m scripts.encrypted_backup export /app/backups/portable-001.tbackup`. Пароль запрашивается интерактивно и **не** появляется в истории команд.
- Заберите файл защищённым способом, например `docker compose cp app:/app/backups/portable-001.tbackup ./portable-001.tbackup`, и сохраните отдельно от VPS. **Автоматическая удалённая выгрузка в этой версии не реализована.**
- Для проверки импорта используйте **новый путь**: `python -m scripts.encrypted_backup import /путь/portable-001.tbackup /путь/новая-база.sqlite3`. Сначала подтвердите целостность, совпадение бота, наличие всех таблиц и затем отдельно поменяйте `DATABASE_PATH` после остановки старой копии. Не подменяйте активную базу.
- Нельзя терять парольную фразу. Без неё расшифровка резервного файла не предусмотрена. Пароль и копия должны храниться раздельно.

### Обновления

1. Остановите ввод новых заявок на время перехода; сделайте проверенный бэкап.
2. Соберите новый образ командой `docker compose build`, затем `docker compose up -d`. **Не запускайте второй экземпляр с тем же токеном.**
3. Проверьте `/ready`, `/health`, журналы, профили и записи. Данные и сертификаты лежат в **именованных томах**, а не внутри обновляемого образа.
4. Сохраняйте копию предыдущего кода/конфигурации для отката. Восстановление старой версии кода не отменяет новых заявок, если не восстанавливали старую базу — перед откатом оценивайте совместимость схемы.

## Что ещё требуется перед коммерческой эксплуатацией

- Фактический запуск Docker, автообновление сертификата, работа на реальном Android/iPhone и приемочные сценарии клуба.
- Наблюдение за сервером снаружи, аварийные оповещения, автоматические защищённые **удалённые** бэкапы с проверкой восстановления на другой машине.
- Согласованные правила игр и бильярда, политика доступа сотрудников, обработка персональных данных, фирменное оформление и клиентские проверки Google Sheets.
- Документированный процесс обновления, кто владеет VPS/доменом и кто обслуживает систему.

**Важно:** этот Docker-набор является отдельным вариантом для VPS. На Windows пока используйте `START_WINDOWS.bat` и `START_TUNNEL_WINDOWS.bat`. Они запускают сервер только на `127.0.0.1:8000`; наружу Mini App открывается через отдельный тестовый туннель.
