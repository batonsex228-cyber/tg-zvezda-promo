# ТУРИСТ v0.11.0 — шифрованные переносимые копии

Добавлена возможность сохранить базу в `.tbackup` для ручной передачи на другой защищённый носитель/сервер. Используются SQLite Online Backup API, проверка целостности, **AES-256-GCM**, Scrypt с уникальной случайной солью и случайный nonce. Файл нельзя восстановить без введённой парольной фразы.

## Windows

1. Закройте неизвестные программы, убедитесь, что диск доступен; штатный SQLite-бэкап можно сделать даже при работающем боте.
2. Запустите `EXPORT_ENCRYPTED_WINDOWS.bat`, укажите новый путь с `.tbackup` (например `D:\tourist-2026-11-05.tbackup`). Файл назначения не должен существовать.
3. Введите **длинную уникальную парольную фразу** (минимум 14 символов) и повторите её. Символы скрываются; пароль нигде не записывается. Поместите копию в закрытое хранилище **вне компьютера** и сохраните пароль отдельно.
4. Для испытания восстановления запустите `IMPORT_ENCRYPTED_WINDOWS.bat`: укажите исходный `.tbackup` и **новый ещё не существующий** путь `.sqlite3`. Программа проверит аутентичность, SQLite и принадлежность бота. Рабочая база не меняется.
5. При неправильной фразе или повреждении зашифрованного файла новый файл SQLite будет удалён. Нельзя направлять восстановление поверх текущего `DATABASE_PATH`.

## Из командной строки

```bash
python -m scripts.encrypted_backup export /backup/tourist-copy.tbackup
python -m scripts.encrypted_backup import /backup/tourist-copy.tbackup /recovery/tourist-restored.sqlite3
```

Никогда не вводите пароль через `--password` в командной строке, `.env` или текст чата. Инструмент не поддерживает такую опцию. Отдельно проверьте, что новое хранилище действительно доступно другому компьютеру. **Текущая версия не делает автоматическую выгрузку в облако**, не управляет паролями и не заменяет регламент резервирования.
