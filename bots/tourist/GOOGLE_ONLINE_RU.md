# Google Sheets — безопасная проверка подключения (v0.13.0)

Проверка **не изменяет** Google Таблицы и **не читает содержимое ячеек**. Запрашиваются только метаданные и список вкладок. Это позволяет проверить, что сервисному аккаунту доступна таблица, **но не доказывает права на запись**.

1. В Google Cloud создайте сервисный аккаунт и JSON-ключ по правилам Вашей организации. Сохраните JSON только на защищённом компьютере/сервере. Не кладите его в ZIP, Git или папку Mini App.
2. Откройте нужную Google Таблицу и предоставьте сервисному аккаунту доступ к ней. Для реальной синхронизации потребуются права редактора.
3. В `.env` укажите `GOOGLE_SHEET_ID` и `GOOGLE_CREDENTIALS_FILE` (абсолютный путь либо путь от корня проекта).
4. На Windows запустите `CHECK_GOOGLE_ONLINE_WINDOWS.bat`; на другой системе — `python -m scripts.check_google_online`.
5. Сообщение `Метаданные таблицы прочитаны` означает, что аутентификация и чтение метаданных прошли. Для проверки реальной **записи** после согласования с клиентом используйте отдельную **тестовую** Google Таблицу и `python -m app.cli sync-now`.

**Безопасность:** диагностический скрипт никогда не печатает токены, email, ID таблицы, путь к ключу или приватные сообщения об ошибках API. При сбое выдаёт только тип стадии ошибки. Не путайте успешно прочитанные метаданные с гарантией записи, стабильности фоновой синхронизации или корректности разрешений на персональные данные.

При передаче клиенту пользуйтесь **сервисным аккаунтом и таблицей клиента**, а не личной таблицей разработчика. Не запускайте `sync-now` на рабочей таблице до её резервного копирования — это зеркальная выгрузка из SQLite, а не двусторонняя синхронизация.
