# «Турист» v0.14.0 — оставшиеся шаги до клиентской приёмки

**Ориентировочная общая готовность: 89% (+1 процентный пункт относительно v0.13.0).** Это инженерная оценка по готовому коду, а не доказательство полной работоспособности интеграций.

## Завершено на этапе 14

- Повторная отмена идемпотентна для игр и бильярда; дубли журналов/уведомлений исключены в регрессионных проверках.
- Снижено раскрытие служебных данных из публичного API расписания.
- Владелец Mini App может явным действием повторить только временно неотправленные системные уведомления, не затрагивая отправленные, постоянные ошибки и напоминания.
- Проверены API, SQLite, роли, браузерный сценарий нового действия и прежние пользовательские сценарии на синтетических учётных данных.

## До реального запуска

1. **Ваш тестовый BotFather-бот:** заполнить BOT_TOKEN в локальном `.env`, OWNER_TELEGRAM_ID, пройти FIRST_RUN_CHECK_WINDOWS и впервые открыть `/start`, `/register`, `/schedule`, `/app` двумя Telegram-аккаунтами.
2. **Mini App на Android и iPhone:** HTTPS, проверка подписи `initData`, повторное открытие, время, формы и ошибки сети.
3. **Google Sheets:** доступ сервисного аккаунта, отдельная тестовая таблица, первая реальная запись и восстановление после сетевого сбоя.
4. **Клиентское ТЗ:** правила мафии/покера/бильярда, количество столов, часы работы, оплата при необходимости, контент и финальный дизайн.
5. **VPS + HTTPS:** реальная установка Docker, Caddy, домен, автоматический рестарт, мониторинг, обновление без потери базы.
6. **S3:** настроить собственный bucket/доступы, подтверждённую зашифрованную выгрузку и восстановление на другом устройстве.
7. **Приёмка:** проверить UAT_CHECKLIST_RU.md с ответственным сотрудником клиента, передать секреты и аккаунты владельцу.

Автотесты и Chromium без настоящего Telegram **не закрывают** пункты 1–7.
