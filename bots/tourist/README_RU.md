# ТУРИСТ v0.14.0 — контроль повторных запросов и надёжности уведомлений

**Текущая версия: 0.14.0. Локальных автотестов: 225/225.** Полная сборка: Telegram-бот, Mini App (сайт на HTML/CSS/JS), FastAPI, SQLite, админка, расписание, бильярд, Google Sheets, резервирование, Windows и серверные скрипты. Данные и ключи клиента в сборку не входят.

## Новые возможности v0.14.0

- Повтор POST-запроса об отмене (после обрыва сети) для уже ожидающей отмены заявки теперь возвращает тот же статус без новой записи в журнале и без второго уведомления администрации. Работает для игр и бильярда.
- Публичное `/api/schedule` больше не раскрывает `created_by` (Telegram ID сотрудника, создавшего мероприятие) и другую внутреннюю SQL-метаинформацию. Поля, необходимые для расписания и подсчёта мест, сохранены.
- Только **владелец** может вручную вернуть в очередь не доставленные **системные** уведомления после известных временных ошибок сети/Telegram. Кнопка находится в Mini App → Администратор → Обзор → Состояние системы.
- Повтор не затрагивает уже отправленные уведомления, постоянные ошибки `HTTP 400/401/403/404`, напоминания и чужие очереди. Максимум 20 сообщений за одно нажатие.
- В интерфейсе перед повтором показывается подтверждение: Telegram API не обеспечивает математическую гарантию доставки «ровно один раз», при неизвестном исходе возможен повторный показ сообщения.
- Добавлен отдельный браузерный тест `python -m scripts.owner_recovery_browser_smoke` (опционально требует Playwright и Chromium); остальные тесты запускаются обычным `TEST_WINDOWS.bat`.

**Важно:** это улучшение локальной надёжности. Отправка живых сообщений, Windows-окружение и Mini App внутри настоящего Telegram должны быть испытаны на Вашем компьютере и клиентских устройствах. Процент готовности ~89% — оценка, не измеренный SLA.

## Кратко: что нового

- `scripts/recover_to_new_db.py` и `RESTORE_TO_NEW_DB_WINDOWS.bat` — восстановление проверенной резервной копии **только в новый `.sqlite3` файл**, ни один существующий файл не перезаписывается. Если бэкап привязан к другому Telegram-боту, операция отклоняется. Текущая `.env` не меняется.
- `scripts/recovery_drill.py` и `RECOVERY_DRILL_WINDOWS.bat` — безопасная репетиция восстановления: создаёт временную копию живой SQLite, восстанавливает её во второй временный файл, проверяет целостность, количество записей и удаляет временную папку.
- Новый read-only API `/api/admin/operations` — только для владельца. Mini App показывает состояние базы, свободное место, очередь Telegram-уведомлений, состояние Google Sheets и конфигурацию HTTPS. **Ни токены, ни пути к файлам, ни персональные данные гостя туда не передаются.**
- Ошибки Google Sheets сохраняются как короткое техническое имя класса, а не сырые строки исключений (которые могут содержать чувствительные сведения).
- Тесты расширены: 144 успешных автоматических теста. Отдельно пройдены FastAPI smoke, сквозная синтетическая Telegram-авторизация, Chromium и JavaScript syntax check.

## Как установить в Windows

1. Распакуйте весь ZIP в отдельную папку, например `C:\TOURIST_V010`. **Не смешивайте файлы разных версий.**
2. Запустите `SETUP_WINDOWS.bat`. Для первого запуска нужен интернет; установщик ставит библиотеки в `.venv`. Рекомендуется Python 3.12.
3. Скопируйте локально существующие `.env` и базу **того же** Telegram-бота из v0.9.0, только после остановки старого процесса. Если это первый запуск, `.env` создастся из `.env.example`; токен сохраняйте только у себя.
4. Выполните `FULL_QA_WINDOWS.bat`, `FIRST_RUN_CHECK_WINDOWS.bat`. Запускайте `START_WINDOWS.bat` для обычного бота; `START_TUNNEL_WINDOWS.bat` — для тестирования Mini App по временной HTTPS-ссылке. Не запускайте два режима одновременно.
5. В Mini App откройте **Админ → Обзор**: владелец увидит «Состояние системы», администратор без роли владельца — нет.
6. После появления рабочей базы запустите `RECOVERY_DRILL_WINDOWS.bat`: он проверит сам процесс восстановления без изменения рабочей базы.

## Как восстановить данные после сбоя

**Сначала остановите программу.** Перед попытками восстановления сохраните старые SQLite и `.env`, даже если база кажется повреждённой. Помните, что SQLite может использовать отдельные файлы WAL/SHM во время работы: не копируйте их вручную из запущенного процесса; используйте штатный архиватор.

1. Выполните `RESTORE_CHECK_WINDOWS.bat` или `python -m scripts.restore_check "путь_к_бэкапу.sqlite3"`, чтобы проверить выбранную копию.
2. Запустите `RESTORE_TO_NEW_DB_WINDOWS.bat` (или напрямую `python -m scripts.recover_to_new_db "путь_к_бэкапу.sqlite3" "путь_к_новой_базе.sqlite3"`). **Второй путь обязан указывать на несуществующий `.sqlite3`** в заранее созданной папке.
3. Убедитесь, что программа напечатала сообщение об успешной проверке. При другом `BOT_TOKEN` восстановление привязанной базы отклоняется.
4. Только после этого откройте `.env` и поменяйте `DATABASE_PATH` на новый файл, оставив исходную базу как резерв. Выполните `CHECK_WINDOWS.bat` и запустите бота.
5. Проверьте профили, события и заявки в Mini App. Помните: новые записи, появившиеся **после** даты копии, автоматически восстановлены не будут.

**Важное ограничение:** резервные копии содержат телефоны и данные гостей. Они НЕ зашифрованы и сохраняются локально. Не выкладывайте их в общий доступ и не отправляйте клиентам в переписке. Для коммерческого запуска по-прежнему необходимы защищённое удалённое хранение и отдельная проверка его восстановления. Режимы реального Telegram, Windows cmd, Google Sheets и Cloudflare нужно испытать с вашими доступами.

Держите личный токен только в локальном `.env`.

## Быстрый первый запуск с новым BotFather-ботом

1. Распакуйте ZIP полностью, например в `C:\TOURIST_V08`. Не запускайте `.bat` из предпросмотра архива. Оставьте v0.7.0 как резервную копию.
2. Запустите **`SETUP_WINDOWS.bat`**. Нужен интернет и Python 3.11–3.13; Windows-установщик создаст `.venv` и поставит `aiogram`, FastAPI и остальные библиотеки.
3. В `.env` (создаётся установщиком из `.env.example`) укажите `BOT_TOKEN=ваш_токен_BotFather`, `DEMO_MODE=false`, `WEBAPP_URL=` (пока пусто). Оставьте `OWNER_TELEGRAM_ID=0`, если не знаете свой Telegram ID. **Никому не отправляйте файл `.env` и токен.**
4. Запустите **`FIRST_RUN_CHECK_WINDOWS.bat`**. Скрипт проверит Python и настройки, базу, свободный порт 8000, `getMe` и `getWebhookInfo`. Не отправляет никаких сообщений пользователям и не отключает webhook автоматически.
5. Запустите **`START_WINDOWS.bat`**; откройте своего бота и напишите `/start`, затем `/id`. Остановите скрипт `Ctrl+C`, внесите полученный числовой ID в `OWNER_TELEGRAM_ID=` и запустите снова. Пройдите `/register`, `/schedule`, `/my`, `/admin`.
6. Для тестирования настоящей Mini App сначала **остановите `START_WINDOWS.bat`**, затем положите `cloudflared.exe` в `.tools` или установите его в PATH и запустите **`START_TUNNEL_WINDOWS.bat`**. После появления адреса HTTPS отправьте боту `/start` или `/app` и нажмите кнопку **«Открыть Mini App»**. Не нужно вручную прописывать временную ссылку в `.env` — скрипт передаёт её дочернему процессу.
7. Проверьте на смартфоне регистрацию, заявку на игру, решение администратора, уведомление, отмену и бильярд. Пока не объявляйте бота действующим для гостей клуба.

**Внимание:** порт 8000 может использовать только одна копия программы. Туннель откажется запускаться, если там уже другая программа. Не запускайте обычную версию и туннель одновременно. После остановки тестового туннеля кнопка меню сбрасывается на стандартную; старые кнопки из сообщений всё ещё могут вести на устаревшую ссылку. Используйте свежий `/start`.

## Новое в v0.6.0 — проверка передачи клиенту, защита данных и браузерный аудит

1. **Блокировка чужой базы до миграции.** При реальном запуске сначала читаем привязку SQLite к токену, не меняя содержимое, и только затем выполняем обновление схемы. Если токен не совпадает — запуск остановится без изменений в базе. Для клиентского бота создайте другую `DATABASE_PATH`.
2. **Единые пути.** Относительные пути к SQLite и Google JSON-ключу теперь отсчитываются от папки проекта, а не от того, из какого каталога Windows запустил Python.
3. **Корректный статус при повторе.** POST записи и бильярда возвращает реальный статус заявки из базы (`pending`, `confirmed`, `cancelled` и т.д.), даже при повторе того же `X-Idempotency-Key` после сетевого сбоя.
4. **Проверяемые резервные копии.** `BACKUP_WINDOWS.bat` делает горячую SQLite-копию; если базы ещё нет, программа не создаёт пустую заготовку. `RESTORE_CHECK_WINDOWS.bat` проверяет целостность, внешние ключи и обязательные таблицы без изменения рабочей базы.
5. **Защита HTTP.** Добавлены заголовки Content-Security-Policy, Permissions-Policy; убраны обычные access-логи Uvicorn с query-параметрами. Telegram Web оставлен в разрешённых источниках отображения, чтобы не блокировать Mini App в браузерном Telegram. Приложение по-прежнему слушает только 127.0.0.1.
6. **Полный тестовый сценарий.** 95 автотестов, signed Telegram API E2E без настоящего токена, обычный smoke и Chromium-клики по основным разделам. Для Windows есть `FULL_QA_WINDOWS.bat` (автотесты, локальный smoke и диагностика демо), который можно запускать ещё до получения токена.

**Проверка с реальным BotFather-токеном, Google Sheets и HTTPS внутри Telegram НЕ выполнена** — потребуется отдельный живой тест с Вашими доступами на Windows. Не отправляйте токен в чат или скриншоты.

## Новое в v0.5.0 — стабильность Mini App и подготовка к BotFather

1. **Повтор запроса без второго бронирования.** Mini App передаёт `X-Idempotency-Key` при записи на игру и бронировании бильярда. SQLite атомарно хранит отпечаток данных запроса и ID заявки. Повтор с тем же ключом и теми же данными возвращает тот же ID без повторного уведомления администратору. Другие данные с тем же ключом отклоняются. Срок хранения ключей — 48 часов. Старая логика Telegram-команд сохранена.
2. **Общие настройки времени.** Сайт читает безопасный `/api/config` (`CLUB_TIMEZONE`, горизонт записи), а не жёстко форматирует даты по московскому времени. По умолчанию сохранён `Europe/Moscow` для Новомосковска.
3. **Обработка сбоев сети в Mini App.** Таймаут 15 секунд, уведомления при отключении/восстановлении интернета, защита от случайных двойных кликов и от устаревших ответов поиска гостей и занятых интервалов бильярда.
4. **Онлайн-проверка тестового Telegram-бота.** `CHECK_TELEGRAM_ONLINE_WINDOWS.bat` вызывает только `getMe` и `getWebhookInfo`: проверяет, действительно ли токен принадлежит боту, и предупреждает о включённом webhook, который мешает long polling. Никаких сообщений не отправляет. Требует интернет, токен скрыт.
5. **Telegram 429.** Очередь сообщений учитывает `retry_after`, возвращённое Telegram, и не форсирует немедленные повторные попытки. Отправка по-прежнему допускает редкие дубликаты при неясном результате удалённой доставки.
6. **Демо-сервер без импорта aiogram.** Локальный сайт может быть запущен независимо от Telegram, хотя обычный установщик ставит все зависимости.
7. **Повторяемая проверка браузера.** Дополнительная (необязательная) команда `python -m scripts.browser_smoke` запускает полноценный Chromium-тест с временной БД, не трогая клиентские данные. Потребуются отдельно `playwright` и Chromium.

## Что усилено в v0.4.0

1. **Привязка базы к конкретному Telegram-боту.** При первом живом старте в БД сохраняется только SHA-256-отпечаток токена. Если потом токен меняется, повторный старт с **той же** БД блокируется с сообщением, не удаляя данные. Это предотвращает передачу чужих админских прав и попытки отправить старую очередь от нового бота. Для клиентского токена просто задайте **новый `DATABASE_PATH`** (например, `data/tourist_client.sqlite3`). Предварительно сделайте резервную копию старой БД.
2. **Устойчивее отправка уведомлений.** Перед отправкой задания атомарно получают временную блокировку в SQLite: два фоновых отправителя не заберут одно сообщение одновременно. После сбоя процесса повтор возможен после истечения блокировки. Это доставка *at-least-once*: редкий повтор после неясного ответа Telegram всё ещё возможен.
3. **Безопаснее Telegram-авторизация.** Подписанные, но неправильно сформированные объекты `user` теперь отклоняются как ошибка авторизации, а не приводят к внутренней ошибке 500. Срок и подпись `initData` проверяются сервером.
4. **Google Sheets.** Исправлено состояние «синхронизировано», когда первоначальная пустая база данных ещё ни разу не выгружалась. Ошибки Google теперь не останавливают будущие попытки синхронизации. Добавлена миграция поля `synced_once`.
5. **Расширенные тесты** подписанной Mini App, смены токена, прав доступа, синхронизации Google (на заглушке), статусов Telegram API (на заглушке), параллельных бронирований, резервного копирования и восстановления после миграции.

Остальные функции предыдущей версии сохранены: профиль, уникальный ник, расписание и лимиты, подтверждение администратора, запросы отмены, история, админ-обзор и отложенные напоминания (по умолчанию выключены).

## 2. Когда создадите тестового бота через @BotFather

В `.env` в корне проекта заполните:

```ini
BOT_TOKEN=ТОКЕН_ОТ_BOTFATHER
WEBAPP_URL=
OWNER_TELEGRAM_ID=0
DATABASE_PATH=data/tourist.sqlite3
CLUB_TIMEZONE=Europe/Moscow
DEMO_MODE=false
GOOGLE_SHEET_ID=
GOOGLE_CREDENTIALS_FILE=
SYNC_INTERVAL_SECONDS=45
REMINDER_HOURS_BEFORE=0
```

`BOT_TOKEN` вводится **только на Вашем компьютере**. Не присылайте токен в переписку, не включайте `.env` в передаваемый ZIP и не публикуйте его в GitHub. Установите `OWNER_TELEGRAM_ID` в **числовой** ID владельца. Если пока его не знаете — оставьте `0`, запустите бота и отправьте `/id` в личные сообщения; впишите ответ в `.env`, затем перезапустите.

После создания бота выполните **`CHECK_TELEGRAM_ONLINE_WINDOWS.bat`** — появятся имя бота и состояние webhook. При ошибке токена или сети не переходите к запуску.

Запуск: сначала **`CHECK_WINDOWS.bat`**, исправьте строки `[ERROR]` (предупреждение о пустом `WEBAPP_URL` допустимо), затем **`START_WINDOWS.bat`**. В Telegram проверьте `/start`, `/register`, `/schedule`, `/my`, `/admin`, `/id`. Командная строка должна оставаться открытой. Не запускайте параллельно вторую копию с тем же токеном и БД.

**Для настоящего Mini App в Telegram** нужен публичный **HTTPS**. Во время тестов установите с официального сайта Cloudflare `cloudflared.exe` в `.tools\cloudflared.exe` и используйте **`START_TUNNEL_WINDOWS.bat` вместо `START_WINDOWS.bat`**. Он получит временный HTTPS-адрес и запустит бота с этим адресом. После каждого перезапуска отправляйте `/start` заново. Quick Tunnel — только для разработки, не для постоянного клуба.

Официальная документация: https://core.telegram.org/bots/webapps, https://docs.aiogram.dev/en/latest/, https://developers.cloudflare.com/cloudflare-one/connections/connect-networks/do-more-with-tunnels/trycloudflare/.

## 3. Смена тестового Telegram-бота на клиентского

**Не переносите администраторов и пользователей тестового бота автоматически.** Сама смена токена не переносит Telegram-чаты или подписчиков и не означает передачу управления чужим ботом. Клиент создаёт **своего** бота в собственном @BotFather и сам владеет его токеном.

1. Остановите бот и HTTPS-туннель, сохраните копию `.env` и запустите `BACKUP_WINDOWS.bat` для старой БД.
2. Измените в `.env` **три поля**: `BOT_TOKEN` на новый клиентский токен, `OWNER_TELEGRAM_ID` на числовой ID клиента, `DATABASE_PATH` на **новый ещё не существующий файл**, например `data/tourist_client.sqlite3`.
3. Убедитесь, что `DEMO_MODE=false`. Выполните `CHECK_WINDOWS.bat`, затем `START_WINDOWS.bat` или `START_TUNNEL_WINDOWS.bat` для Mini App.
4. Клиент запускает `/start`. Проверяете роль владельца и удалённый доступ сотрудников в админке. Тестовых гостей не нужно пересоздавать от старого бота.

Если в новой версии Вы продолжаете использовать **то же самое тестовое** BotFather-бот и переносите действующую v0.3.0 БД, оставьте прежний `DATABASE_PATH` и токен: схема автоматически обновится без удаления данных. При старой базе v0.3.0 отпечатка токена ещё нет — он запишется при первом живом старте. Поэтому **не подменяйте токен до первого запуска на чужой действующей БД**.

При несовпадении отпечатка запуск останавливается с подсказкой изменить путь БД. Старые данные не удаляются. **Не удаляйте `.sqlite3` для обхода ошибки, не сделав копию.**

## 4. Проверка функционала по ролям

**Гость:** `/register` → имя, телефон и уникальный ник → открыть расписание → отправить заявку → увидеть «ожидает подтверждения» → получить решение администратора → при необходимости запросить отмену. Бильярд: выбрать время, 1–4 часа, количество гостей, проверить свободные интервалы, отправить заявку. Бронирование доступно до 7 дней вперёд, часы работы клиента ещё не утверждены.

**Администратор:** «Админ» → «Заявки» → подтвердить/отклонить заявку либо запрос на отмену → проверить смену статуса у гостя. Старший и владелец создают и редактируют события; в разделе «Гости» назначаются роли в соответствии с полномочиями. В «Истории» доступны действия администрации.

**Уведомления:** ставятся в локальную очередь, отправляются фоном и могут повторяться после временных сетевых ошибок. В демо без токена **не уходят** в Telegram. Напоминания включаются через `REMINDER_HOURS_BEFORE=1..168` после согласования с заказчиком; значение `0` выключает функцию.

**Google Sheets:** опциональное *одностороннее зеркало*, БД остаётся источником истины. Настройте `GOOGLE_SHEET_ID` и `GOOGLE_CREDENTIALS_FILE` (сервисный JSON-ключ, доступ редактора к таблице). Синхронизация заменяет содержимое рабочих листов. Не редактируйте эти листы вручную, иначе правки будут перезаписаны. В локальном QA используется имитация Google, реальное соединение нужно проверить на собственном аккаунте.

- Для Mini App установить `cloudflared` и использовать `START_TUNNEL_WINDOWS.bat` **вместо** `START_WINDOWS.bat`. После изменения временного URL открыть новое сообщение `/start`.
- Проверить Telegram Mini App и на Android, и на iOS, включая авторизацию, отправку заявки, её одобрение сотрудником и получение уведомления.

**Важно:** если при потере связи после отправки заявки пользователь повторит её из Mini App, версия v0.5.0 использует тот же ключ повтора, пока форма не изменилась. Это защищает от дублирования только при повторе с тем же ключом и в пределах 48 часов. Полной гарантии exactly-once для Telegram-уведомлений нет — Telegram Bot API не предоставляет для `sendMessage` общего ключа идемпотентности.

## Обновление v0.9.0 · автоматические копии

Новое: `BACKUP_INTERVAL_HOURS=24`, `BACKUP_KEEP_DAYS=14` в `.env`, фоновая проверка через 30 секунд после запуска **живого** бота и далее раз в час. Система создаёт проверенную копию только если предыдущая старше заданного интервала. Автокопии публикуются атомарно; очистка старых автоматических копий не затрагивает ручные копии. Состояние выводится в админском разделе «Обзор → Резервные копии» и через `BACKUP_STATUS_WINDOWS.bat`.

На локальном демо без токена фоновое копирование отключено. Рабочий бот должен оставаться запущенным для расписания. Копии сохраняются **в папке проекта** и не защищают от потери всего диска: для реального клуба понадобится отдельное защищённое удалённое хранилище. Чтобы проверить восстановление, выполните `RESTORE_CHECK_WINDOWS.bat`. Скрипт теперь находит как ручные, так и автоматические копии.

Пошаговый перенос со старой версии — `MIGRATION_NOTES_RU.md`. Не обновляйте оригинальную SQLite на работающем процессе и не отдавайте клиенту тестовый токен/базу разработчика. Клиентский бот должен получить собственный токен и отдельную базу.
